### 习惯错 · 第1次 · README 三条粗体未闭合
- 现象：`README.md` 第 64~66 行（自动采集 / 测试 / skipif 三条）每行只有 1 个 `**`，没有闭合；grep 实测，三行各自命中一次。

- 下次自检：`grep -n "\*\*" README.md`，每一行 `**` 的个数必须是偶数。

### 习惯错 · 第2次 · 用 print 代替赋值
- 现象：今日两次——`print=(...)` 写法两次；`round(r,3)` 算完没赋给变量，下一行仍然 print 旧值（会话记录，未留命令输出）。
- 根因：把「打印」当成「算完」，计算语句没有落进变量就开始写输出。
- 正确做法：先 `x = 表达式`，再 `print(x)`；两行不能合并。
- 下次自检：运行前在项目目录搜 `print=`，命中即改（`findstr "print=" *.py`）。

### 习惯错 · 第1次 · 一个 commit 混两件事
- 现象：commit `abf3ecd` 除进度日志外，还夹带 `PLAN.md`「三、每日节奏」表新增一行 + 硬规矩新增一行（`git show abf3ecd -- PLAN.md` 实测：4 insertions）。
- 根因：提交前不看 diff，把工作区里所有改动当成「今天的活」。
- 正确做法：一个 commit 只对应一个动作，无关改动先 `git restore --staged` 拆出去或单独提交。
- 下次自检：`git diff --cached` 通读一遍，出现与本次动作无关的行就拆。

### 技术错 · 第1次 · 摘要脚本丢了口径
- 现象：`summarize.py` 输出 5 行数字（90 / 33 / 57 / -0.39 / 30.2），首行没有数据源，也没有抓取时间；Pearson r 与 `stats.py` 重复实现（`python summarize.py` 实测）。
- 根因：只关心「数字算对了」，没关心「这个数字是哪个源、哪个时刻的」；复制了计算，没复制 `analyze.py` 里的数据自检两行。
- 正确做法：任何产出数字的脚本，首行打印 `数据源 | 抓取时间 | 行数`；跨源快照不进同一段摘要。
- 下次自检：把 15:35 那份（同花顺 90 行）与主源（东财 496 行）分别跑一遍，摘要里必须出现源名，否则不许往下做。
