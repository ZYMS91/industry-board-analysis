## ② 错误清单（4 条；习惯错在前）

### 习惯错 · 未入库（缺三问）
- 现象：`PLAN.md`、`reports/错误库.md` 从 10-25 09:53 起一直未提交，10-26 07:56 实测 `git status --short` 仍显示两行 `M`。
- 根因：把「改完文件」当成「做完」，commit 被当成可选的收尾，而不是回滚点。
- 正确做法：写完复盘文档立刻 `git add -A && git commit -m "..."`，commit message 写做了什么。
- 下次自检：`git status --short` 输出必须为空；不空就是没做完。
- 第1次（待你口述三问后才入库，我不替你补）

### 技术错 · 已入库 第1次
- 现象：`tests/test_pick.py` 第 17 行 `def test_pick_all_empty_columns():` 缩进 4 格，pytest 只收 2 个测试。
- 根因：写第二个 `def` 时顺着上一行缩进敲，没检查层级；缩进是 Python 的分块语法，不是排版。
- 正确做法：模块级函数顶格写。
- 下次自检：`pytest --collect-only -q` 里 `::test_` 条数 = 文件里 `def test_` 个数。

### 习惯错 · 未入库（10-25 你选择不补三问，不计次数）
- 现象：在 `>>>` REPL 里敲 `.venv\Scripts\python.exe -m pytest -q` → `SyntaxError`，测试代码一度只存在内存里、没有落盘。
- 根因：分不清终端（CMD）和 Python 解释器（`>>>`）是两个不同环境。
- 正确做法：先退到 CMD 提示符（`exit()`），再敲整条命令。
- 下次自检：看到提示符是 `>>>` 就说明你在 Python 里，任何 shell 命令都不能敲。

### 习惯错 · 未入库（同上，不计次数）
- 现象：光标停在 `utils.py` docstring 里时粘贴 `git add -A`，文件被污染成 `其git add -A实是错的`。
- 根因：粘贴前不看光标位置。
- 正确做法：命令只粘到终端窗口，不粘进编辑器。
- 下次自检：粘贴后先看光标所在行是不是注释/字符串内部。
