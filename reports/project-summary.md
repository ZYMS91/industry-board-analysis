# 项目总结：A 股行业板块数据管线

> 数据截至 2026-11-06，全部为实测值。

## 一、一句话

一个每天收盘后自动运行的数据管线：采集 90–496 个行业板块行情 → 计算 5 个指标 → 用 AI 生成带数字溯源的研报 → 通过 HTTP 接口对外提供。

## 三、架构

```
update.py  ── 唯一联网的脚本 ──→ data/industry_YYYYMMDD_HHMMSS.csv
   │                                   │
   │ 东财主源（496 板块）                │ latest.csv
   │ 同花顺备源（90 行业）              ↓
   └─ 失败自动切换 ──────────→  summarize.py
                                    ├── build_nums()      算 5 个指标
                                    ├── market_mood()     判断普涨/普跌/分化
                                    ├── generate()        LLM 或模板
                                    └── check_numbers()   数字溯源校验
                                            ↓
                                    app.py（FastAPI）
                                            ↓
                                    GET /summary → JSON
```

**关键约束：只有 `update.py` 联网。** 其余全部只读本地 CSV，所以数据源挂了、断网时分析和报告照常能跑。

## 四、五个核心设计（面试重点）

### 1. 分层与解耦
采集、分析、统计、出图、报告、服务各自独立脚本。唯一联网的是采集层。数据源故障不影响下游。

### 2. 数字与评述分离
- 程序算出 5 个指标，用 f-string 注入报告
- **LLM 只写定性评述，不接触任何数字**
- 它不知道具体值，就编不出来

### 3. 双向数字溯源校验
报告生成后，用正则抽出所有数字，与源数据做**双向**比对：
- 文案里的数字不在白名单 → 拒绝输出（退出码 1）
- 白名单里的值没出现 → 同样拒绝
- **单向下限不够**：5 个重复的 `90` 曾骗过「数量下限」检查

### 4. 方向由程序定，措辞由 AI 写
`market_mood()` 按涨跌占比判断「普涨 / 普跌 / 分化」，把**方向词**喂给 LLM，数字仍然不给。
- 修掉过一个硬 bug：数据 429 跌 67 涨，LLM 评述说「普涨」——因为它不知道方向，只能瞎猜

### 5. 全链路降级
| 层 | 失败时 |
|---|---|
| 数据源 | 主源失败切备源；两源都失败保留上次快照 |
| 字段缺失 | 缺「成交额」→ 跳过相关性与集中度，只输出涨跌分布 |
| LLM | 未配 key / 超时 / 返回含数字 / 返回废话 → 回落模板文案 |
| 接口 | 任何情况返回 200，不返回 500 |

## 五、三个真 bug（最能讲的）

### bug 1：主源成功，反而打崩下游
东财接口恢复，抓到 496 行，比备源 90 行细 5 倍，看起来更好。但它的「成交额」列全是空值 → 相关系数和集中度算出 `NaN` → 报告里出现 `r=nan`、`30.0%` 变成 `nan%`。

**防幻觉校验把 `NaN` 拦下来了**（`NaN` 不在白名单）。之后在 `build_nums` 里加了数据可用性检查，让它在算之前就拒绝坏数据。

**教训：接口返回 200、抓到行数更多 ≠ 数据可用。**

### bug 2：数字全对，结论说反
报告写「上涨 67、下跌 429」（普跌），AI 评述说「普涨」。

根因：为了让 AI 不编数字，完全不给它数据 —— 它就不知道方向，只能瞎猜，蒙对蒙错各半。

**修法：程序判断方向（普跌），把方向词给 AI，数字仍然不给。**

**教训：防幻觉不能靠信息剥夺，要靠信息来源可控。**

### bug 3：校验形同虚设
`check_numbers` 最初用「找到的每个数字都在白名单里」做判断。文案里一个数字都没有时，空集合恒真 → 打印「校验通过：0 个数字」。

这个问题藏了两周才暴露，因为没人喂过「不含数字的文案」。

**修法：双向校验（差集检查）+ 正向测试（正常文案必须通过）。**

**教训：只测「该拒的拒了」，不测「该过的过了」，代码可以坏成任何样子。**

## 七、3 分钟面试版（照着说）

> 我做了一个 A 股行业板块的数据管线，解决的是「人工每天翻 90 个板块太慢、而且有几个数人工算不出来」的问题。
>
> 技术上分三层：采集层唯一联网，主源东财、备源同花顺，失败自动切换、两源都挂就保留上次快照；计算层算 5 个指标，包括涨跌分布、相关系数、成交额集中度；报告层用 AI 生成评述，但**数字全部由程序注入，AI 不接触任何数字**。
>
> 最难的不是写功能，是让结果可信。我遇到过一个最隐蔽的 bug：报告里数字全对，但 AI 评述说「普涨」，而实际是 429 个板块下跌——因为我不给它数据，它只能瞎猜。后来改成由程序判断方向、把方向词告诉 AI，数字仍然不给。
>
> 还有一次主数据源恢复，抓到 496 行，看起来比备源好，但成交额列全是空的，所有指标算出 NaN，被我的防幻觉校验拦下来了。
>
> 现在项目 908 行、14 个测试全绿、每个交易日 15:35 自动采集、通过 FastAPI 提供 `/summary` 接口。全新环境 `pip install` 后能直接复现测试结果。
