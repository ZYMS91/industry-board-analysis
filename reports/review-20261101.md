## ② 错误清单

### 习惯错

**1）改完没提交就让 AI 做破坏实验，未提交的 5 行被 `git checkout --` 覆盖（第 1 次）**
- 现象：21:12 加进 `summarize.py` 的 `if re.search(r"\d", comment)` 检查未提交；21:22 我跑 `git checkout -- summarize.py` 恢复 prompt，整文件回到上次 commit，这 5 行消失（会话 5909 记录）。
- 根因：把"文件已保存"当成"改动已保住"；破坏性操作前不 commit。
- 正确做法：让 AI 执行 `git checkout` / `git restore` / `git reset` 前先 commit 当前改动。
- 下次自检：跑这类命令前 `git status --short` 有 ` M ` 就先 commit。

### 技术错

**2）新函数零测试，第 3 次（停止线触发）**
- 现象：`grep -rn "generate\|template_summary\|llm_summary\|check_numbers" tests/` 退出码 1（实测）；`pytest -q` 仍 5 passed。今天新加的 `requests.post` 真调用、评述数字检查、`resp.raise_for_status()` 全部零覆盖。
- 根因：跑旧测试确认"没弄坏"，把"没弄坏"当"新代码被验证"（与 10-29 重构零覆盖、10-31 新增三函数零测试同源）。
- 正确做法：`template_summary` 断言行数/上涨/r 三个值；`generate` 用 monkeypatch 让 `llm_summary` 抛异常、断言返回模板；`check_numbers` 对无数字文案必须 `SystemExit`。
- 下次自检：收工前 `grep -c "def test_" tests/*.py` 的总数必须 ≥ 今天新增函数数。
- **停止线：这个问题没修好之前，不学新内容。**

**3）LLM 没数据也会答"无法确定"，绕过所有数字检查（第 1 次）**
- 现象：破坏实验（把 prompt 改成"请描述今天行情"这类无约束版本）实测输出「今日 90 个板块中…30.0%。 无法确定，因为我没有今天A股实时行情数据。」+「校验通过：5 个数字全部可溯源」。
- 根因：只防"编造数字"，没防"没数据就推卸"；假设模型知道今天行情，却没在 prompt 里给任何数据。
- 正确做法：评述进成品前加拒答检测（含"无法/没有/抱歉/不知道"或长度 <10 字即丢弃）；或把定性结论也由程序从 `nums` 推导，LLM 只做措辞润色。
- 下次自检：任何 LLM 输出拼进报告前，先打印它的字数和是否含"无法/没有"，两者任一异常就丢。

**4）临时探针两连错：放错目录 + key 当变量名（第 1 次）**
- 现象：`tests\test_api.py` 被 pytest 收集，报 `ERROR collecting tests/test_api.py`，原本 5 passed 被破坏；同文件里 `key = os.environ.get("<已隐藏>")` 传的是 key 值，取到 `None`。
- 根因：不知道 pytest 按文件名 `test_*.py` 自动收集；不知道 `os.environ.get()` 括号里要的是变量名不是值。
- 正确做法：临时脚本放项目根目录、名字不以 `test_` 开头（`probe_api.py`）；`os.environ.get("DEEPSEEK_API_KEY")`。
- 下次自检：`ls tests/` 里每个文件名都以 `test_` 开头且只有一个 `def test_` 对应；`grep -n "os.environ.get("` 括号内必须全大写。
